# luna 1.9 password manager

The password manager implements explicit save/update prompts, automatic single-account filling, browser-owned account selection, username-first login, dynamic and common form-less components, same-origin iframes, and manual password management. Edge/Chrome CSV imports preserve existing entries. Password generation uses Node crypto and includes upper/lowercase letters, digits and symbols.

The complete vault (including account metadata) is encrypted with Electron safeStorage; Windows uses DPAPI for the current Windows account. Writes are atomic and contain only encrypted bytes. Encryption unavailability, plaintext storage backends, malformed files or decryption failure stop vault operations without overwriting the original file. The browser state and list API omit passwords.

Page IPC requires a registered browser tab, the real sender frame's secure origin, a matching committed tab/top-level origin and matching origins for every iframe ancestor. Form actions must be same-origin. The sandbox and context isolation remain enabled with Node unavailable to page worlds, including iframe worlds. Only the isolated preload receives fill data, verifies a per-document token and visible current fields, and checks the action again after username input handlers run. It never submits forms. Remote insecure HTTP, extension and internal pages cannot request passwords.

Save candidates expire after two minutes and are held only in memory. Normal browsing-data deletion preserves passwords unless the separate password category is selected. Viewing/editing saved passwords requires local confirmation; plaintext fields are cleared on close/Esc and after 30 seconds of inactivity. This confirmation is not native user reauthentication.

Validation includes six password unit tests (49 total project unit tests) and an Electron smoke suite exercising actual DPAPI encrypted storage, save/update, dynamic/no-form/username-only forms, same-origin iframe filling, cross-origin/action/hidden-form denial, account selection, switches/exceptions, staged login, management, CSV import, restart, sender/action/token boundaries and deletion. Source security, privacy, appearance, menu and feature regression suites pass. Test evidence is in `artifacts/passwords-result.json` and password UI screenshots. The packaging check reruns the password suite against the release executable.

Limitations: local storage only; no cloud synchronization, passkey provider or Windows Hello authentication. Login success cannot be inferred reliably on every site, so save prompts describe a submission. Closed Shadow DOM or unusual website controls may require manual entry. Once filled, the destination website can access its own form values, as with other browser password managers.
