# luna 安全审计与修复

审计日期：2026-10-11。基线版本：1.7.0。修复版本：1.7.1。

本次确认 5 处安全问题：2 处高风险、3 处中风险。均已在源码中修复并加入回归检查。风险等级是本次审计的定性判断，不代表已分配 CVE 或经过第三方认证。

## 范围与方法

审查 Electron 窗口和网页隔离、IPC、扩展桥接和权限、商店安装、扩展解包、下载与本地文件操作、界面输出和 CSP。使用临时用户目录、本地 HTTP 服务、测试 Cookie、测试插件及模拟的商店页面进行复现；没有读取生产 Cookie 或执行下载的程序。

复现结果保存在 `artifacts/security-before.json`；修复后的安全检查结果保存在 `artifacts/security-after.json`。Windows 来源标记缺失还通过真实下载后的 `Zone.Identifier` 读取失败复现，修复后相同检查通过。

## 确认的问题

| 编号 | 等级 | 触发条件与影响 | 修复与验证 |
| --- | --- | --- | --- |
| LUNA-SEC-01 | 高 | 用户安装的插件即使没有声明 `cookies` 权限，也可经桥接接口读取会话 Cookie，包括 HttpOnly。仅获某一网站权限的插件也能读取其他网站 Cookie。潜在影响包括登录凭据泄漏。 | 主进程检查 `cookies` 权限及网站范围；读写操作和事件通知均受约束。无权限测试插件返回无数据，限定 127.0.0.1 的插件读不到 localhost Cookie，范围外写入和撤销权限后的调用被阻止。 |
| LUNA-SEC-02 | 高 | Chrome 商店页面暴露通用 `ipcRenderer.invoke` 包装，页面脚本可指定任意频道与已安装插件 ID。扩展桥接此前仅检查该 ID 已加载，未核验实际发送来源。复现中商店脚本成功冒充插件读取测试 Cookie；这依赖商店页面脚本被攻击者控制，不是任意普通网页都能调用。 | 商店桥使用明确频道与事件白名单，只向顶层商店页面提供；主进程独立比对扩展 frame 的实际 origin 或 worker 的 scope、ID 与会话。商店冒充调用被拒绝；额外测试中的任意网页 IPC 传输也无法伪造插件身份。 |
| LUNA-SEC-03 | 中 | 未获得 `tabs` 或对应网站权限的插件仍能查询网页标题、完整地址和图标。地址可包含登录流程或私有查询令牌；标签事件和填充后的窗口信息存在相同泄漏路径。 | 查询返回值、事件变化信息及窗口中的标签统一清除未授权元数据；包含敏感条件的查询仅返回授权范围内的匹配。`activeTab` 必须由用户动作授予，并绑定一个标签及其来源。测试覆盖同站点第二个标签、跨来源跳转及 Cookie 不随临时授权开放。 |
| LUNA-SEC-04 | 中 | 插件调用 `chrome.tabs.update` 可直接 `loadURL(file:...)`，绕过地址输入和普通网页导航的协议校验。复现中测试本地文件确实被加载，浏览器仍保留之前的网页地址状态。没有据此确认 Node 执行或任意本地文件读取给插件。 | 在桥接入口校验标签和窗口目标地址，仅允许 HTTP、HTTPS 与插件自己的资源页面。`file:`、`data:`、`javascript:`、浏览器内部协议和其他插件页面被拒绝；复测确认原标签不再加载测试本地文件。 |
| LUNA-SEC-05 | 中 | 分段下载由 Node 合并文件，未写入 Windows `Zone.Identifier`。真实测试输出的 exe 没有来源标记，可能使依赖该标记的打开警告或文档保护机制不触发；不等于自动执行文件。 | 在临时文件发布和自动打开之前写入 Internet 区域标记，系统重命名/复制保留该数据流；通过 luna 打开旧分段下载时补写。写入失败会阻止相关完成或打开操作。NTFS 上验证最终文件包含 `ZoneId=3`，来源不含密码、查询令牌或 URL 片段。系统提示行为仍由 Windows 策略与文件类型决定。 |

## 额外加固

- 移除已不再用于工具栏的 `crx:` 图标协议入口，并收窄界面的图片 CSP。
- 扩展动态图标资源使用真实路径及目录边界检查，拒绝相邻目录前缀和越出安装目录的文件链接；对应检查通过。
- 可选网站权限必须属于 manifest 声明的范围，权限撤销后接口和事件立即重新判断。
- 扩展桥安全适配针对当前固定的 `electron-chrome-extensions@4.9.0`，启动时检查必要接口；不兼容时停止加载扩展，后续升级需重新执行安全检查。

## 验证结果

- `npm audit --json`：报告 0 条已知依赖漏洞；`npm outdated --json`：未报告可更新的依赖。
- `npm test`：39 项单元检查通过，涵盖地址、数据、下载完整性、CRX 签名、路径、权限模式和 Windows 来源标记。
- `npm run test:security`：网页无 Node 与浏览器私有接口；Cookie 权限/网站范围、标签元数据/事件、主进程调用者、商店白名单、禁止协议、权限撤销与 activeTab 检查通过。
- `npm run test:features`、`npm run test:context`、`npm run test:store`：原有下载、插件、右键、页面工具和商店流程回归通过。
- 交付时对打包版再次运行安全检查，结果见 `artifacts/security-after.json`。

## 边界与限制

这是一轮源码审查、依赖扫描和定向复现，不是 Chromium 全部代码或第三方插件的完整审计，也未进行引擎模糊测试。npm 公告扫描不能排除 Chromium 未知漏洞。

用户明确授予广泛网站和 Cookie 权限的插件仍可访问授权数据。这里只验证并修复宿主权限边界，不认证 AdGuard、Dark Mode 或其他插件自身的所有行为。

Windows 来源标记需要支持数据流的文件系统。此前下载的文件若直接在浏览器之外打开，本次补丁不会自动给它们补写标记。浏览历史和书签仍按本地 JSON 保存，同一 Windows 用户或管理员可读取这些文件。
